# WS2812B RGB 灯控制设计

## 目标与硬件边界

原理图 `STM32/docs/SCH_导盲犬V3.0电源板.pdf` 只显示 RGB 数据网从 STM32F407VET6 的 PB13 接到外部接口，没有画出外部灯板拓扑。实物表现确认三颗 WS2812B 按 DIN 到 DOUT 级联；固件连续发送三组相同 GRB，将它们作为一颗逻辑灯：三颗灯始终显示相同颜色、亮度和闪烁相位，不实现单灯寻址。

RGB 与 PE7 的普通 `SIGNAL_LED` 是不同功能。现有照明 GPIO 通道保持不变，PB13 专用于 WS2812B 数据输出。

## WS2812B 驱动

采用 PB13 GPIO 和 Cortex-M4 DWT 周期计数器生成约 800 kHz 单线时序。依据 `STM32/docs/RGB手册.pdf`，0/1 高电平目标分别设为 200/550 ns，给软件执行开销留出余量；每次连续发送三组相同的 24 位 GRB 数据时屏蔽中断约 90 us，发送结束后保持低电平 125 us。颜色仅在命令更新或闪烁相位切换时发送，不持续刷新。

该方案不占用新的定时器、DMA 或中断资源，适合一颗逻辑灯且每秒最多约八次输出变化的场景。时序常量根据 `SystemCoreClock` 计算，必须通过示波器实测 PB13 的周期、高电平宽度和复位低电平。

RGB 原始值视为 sRGB，先用 `value²/255` 的 gamma≈2 整数近似转换为线性 PWM，再按独立的 0-100% 亮度缩放，最后以 WS2812B 要求的 GRB 顺序发送。纯色端点保持不变，低饱和度颜色不会因直接线性驱动而过度趋白；状态回读仍保留原始 sRGB 值。

## 状态与闪烁模式

STM32 每次复位后的默认状态固定为：

- 颜色：绿色 `#00FF00`
- 亮度：25%
- 模式：慢闪 1 Hz
- 初始相位：亮

设置只保存在 RAM，不写入 Flash。五种模式为：

| 编号 | 模式 | 行为 |
| --- | --- | --- |
| 0 | 关闭 | 始终输出黑色 |
| 1 | 常亮 | 始终输出缩放后的颜色 |
| 2 | 慢闪 | 1 Hz，50% 占空比，500 ms 切换相位 |
| 3 | 中闪 | 2 Hz，50% 占空比，250 ms 切换相位 |
| 4 | 快闪 | 标称 4 Hz，50% 占空比，受 2 ms 节拍限制每 126 ms 切换相位 |

闪烁复用 TIM6 的 2 ms 应用节拍并在主循环执行。收到新设置后立即从亮相位开始；关闭模式立即熄灭。

## 应用通信协议

USB CDC 与 UART5 继续进入同一个应用协议解析和分发入口。新增帧：

| 帧 ID | 名称 | 方向 | payload |
| --- | --- | --- | --- |
| `0x0C` | `RGB_SET` | 上位机 -> STM32 | `seq + R + G + B + brightness + mode` |
| `0x8C` | `RGB_SET_RESPONSE` | STM32 -> 上位机 | `seq + result` |
| `0x0D` | `RGB_QUERY` | 上位机 -> STM32 | `seq` |
| `0x8D` | `RGB_STATUS` | STM32 -> 上位机 | `seq + R + G + B + brightness + mode + output_on` |

`brightness` 允许 0-100，`mode` 允许 0-4，`output_on` 表示当前闪烁相位。设置响应结果为：`0=成功`、`1=亮度非法`、`2=模式非法`。任何非法设置都保持原状态不变；错误长度不发送设置响应，而是遵循现有协议返回 `0xE1` 长度错误帧。

## Python 协议层

在现有 `stm32_jetson_serial_comm` 包中增加 RGB 帧常量、不可变状态/结果数据类、payload 解码函数，以及 `SerialHost.set_rgb()`、`SerialHost.query_rgb()`。复用现有序号、超时和期望响应校验逻辑，不新增包或独立客户端。

本阶段只提供 Qt 所需的协议能力，不新增 ROS 2 topic、service 或 RGB 命令行工具。

## Qt RGB 页面

在“控制”和“RTK”之间增加独立的“RGB 灯”页：

- “基础色”按钮：红 `#FF0000`、绿 `#00FF00`、蓝 `#0000FF`、白 `#FFFFFF`、黄 `#FFFF00`、青 `#00FFFF`、紫 `#FF00FF`、橙 `#FF8000`。
- “马卡龙色”按钮：樱花粉 `#FFB7C5`、蜜桃橙 `#FFCBA4`、奶油黄 `#FFF1A8`、薄荷绿 `#B8E8D0`、湖水蓝 `#A7D8F0`、薰衣草紫 `#C8B6E2`、杏仁米 `#E8D5C4`、珊瑚粉 `#FF9AA2`。
- 使用 Qt 自带颜色选择器支持任意 RGB，不增加第三方控件。
- 亮度输入范围 0-100%，默认 25%；模式下拉框对应五种固件模式。
- 选择颜色、亮度或模式时只更新编辑区，点击“应用”才发送一条设置命令。
- 状态区显示 STM32 实际回读的色块、`#RRGGBB`、亮度、模式和当前亮/灭相位。
- 页面提供“启用状态回读”开关，默认开启。控制页“轮询与超时”增加 `RGB 状态 Hz`，默认 2 Hz；该行只设置频率，回读开关以 RGB 页面为准。

编辑区颜色、亮度、模式，以及 RGB 回读开关和频率使用现有 QSettings 保存。Qt 重新启动后恢复编辑值，但不会自动下发；STM32 仍从绿色慢闪 25% 开始，直到用户点击“应用”。

## 数据流与错误表现

Qt 应用命令经过 Worker 和 `SerialHost.set_rgb()` 发送；STM32 校验并立即应用后返回结果。Worker 按设置频率调用 `query_rgb()`，把回读状态加入现有遥测对象并发布给窗口。关闭回读只停止 RGB 查询，不影响灯的运行状态或其他轮询。

设置失败在现有命令结果区域和日志中显示，不修改回读显示。RGB 查询超时沿用现有轮询错误处理：记录错误并断开连接，避免界面持续显示已失效的在线状态。

## 验证

- STM32 自动测试：PB13 映射、DWT/GRB 时序编码、亮度缩放、默认状态、五种模式、设置原子性和协议分发。
- Python 自动测试：帧常量、设置编码、响应和状态解码、非法 payload。
- Qt 自动测试：两个颜色分组、自定义颜色、单次应用、实际状态显示、回读开关、频率校验和设置恢复。
- 完整验证：STM32 干净构建、STM32/Python/Qt 全套测试、Qt 离屏启动、App bin 同步比较。
- 实机验收：示波器确认 PB13 时序；验证三灯同步、16 个预置色、0/25/100% 亮度、五种模式、回读启停和长时间串口稳定性。

## 电气风险

原理图中 PB13 到 RGB 接口只有 ESD 保护，未看到 3.3 V 到 5 V 电平转换。如果 WS2812B 由 5 V 供电，STM32 的 3.3 V 高电平可能接近或低于灯珠 VIH 要求。软件不能消除该风险；若实机出现偶发错色、闪烁或温度相关不稳定，应在数据线上增加 74AHCT/74HCT 系列电平转换器，并保留靠近灯端的串联阻尼电阻。
