# DM3.1 Qt 图形化调试上位机设计

日期：2026-07-22

## 1. 目标与范围

开发一套面向内部研发的桌面调试上位机，通过 USB CDC 直连 STM32。
开发环境为 macOS，交付目标为 Windows 和 Linux。首版覆盖：

- STM32 连接、状态监控和通信日志；
- GPIO、风扇和 CS1237 控制；
- 风扇 RPM、超声波和 CS1237 实时曲线；
- CSV 数据记录；
- 应用固件选择、擦除、写入、校验和重启。

首版不包含账号权限、数据库、主题系统、插件、脚本编辑器、多设备并行、
在线更新和面向最终用户的安装引导。PB13 RGB 仍等待硬件协议确认。

## 2. 技术路线

使用 Python、PySide6 Widgets 和现有 `stm32_jetson_serial_comm` 包：

- 继续使用 `SerialDriver`、`SerialHost`、消息解码和 bootloader 模块；
- 串口仍由 pyserial 访问，不另写 Qt `QSerialPort` 协议实现；
- 实时曲线使用 PySide6 Qt Charts，不引入 Matplotlib；
- CSV 使用 Python 标准库 `csv`；
- 使用 `pyside6-deploy` 分别在 Windows 和 Linux 构建目标产物。

全部 Qt 相关源码、测试、依赖清单和打包配置独立放在仓库根目录
`QT_Host/` 子工程中，不写入 STM32 工程或 ROS2 Python 包目录。只有固件大小
校验这类所有调用方都需要的安全修复允许落在现有共享 bootloader 模块中。

macOS 用于日常开发和界面验证。Windows `.exe` 和 Linux 产物必须在对应
平台或对应平台的 CI 环境中构建，macOS 构建产物不跨平台复制。

未采用的路线：

- Qt Quick/QML：界面表现更灵活，但内部工具不值得维护额外的 QML/Python 边界；
- C++ Qt：会重复现有 Python 协议、升级和测试代码；
- Web/Electron：没有浏览器远程访问需求，额外运行时没有收益。

## 3. 结构与数据流

应用保持单进程，只增加一个串口工作线程：

```text
PySide6 Widgets
      │ Qt 命令/信号
      ▼
串口工作线程 ── SerialDriver / SerialHost / Bootloader
      │
      ├── 状态信号 ──> 总览、控制反馈、实时曲线
      ├── 日志信号 ──> 通信日志
      └── 采样信号 ──> CSV 记录器
```

串口工作线程是 USB 连接的唯一所有者。查询、控制和升级命令均在该线程中
串行执行，界面线程不得直接读写串口。

正常模式沿用现有默认轮询频率：状态 0.5 Hz、GPIO 1 Hz、超声波 5 Hz、
CS1237 10 Hz、板载 IO 2 Hz。工作线程每次只发送一个请求并等待对应响应，
避免请求与响应交叉。轮询频率和串口超时可在调试设置中修改。

状态机只有四种状态：`DISCONNECTED`、`APPLICATION`、`BOOTLOADER`、
`UPGRADING`。进入升级时暂停全部普通轮询和控制；结束后重新枚举端口并尝试
恢复应用连接。

## 4. 界面

顶部固定连接栏包含：

- 刷新串口；
- 设备选择；
- 连接/断开；
- 当前模式和链路状态。

主区域包含四页：

### 4.1 总览

显示 STM32 在线状态、六路 GPIO、风扇档位和双路 RPM、KEY1/KEY2、三路
超声波以及 CS1237 原始值、通道和有效状态。

### 4.2 实时曲线

显示风扇双路 RPM、三路超声波距离和 CS1237 原始值。支持曲线选择、暂停、
清空和固定长度滚动窗口。首版不实现数据库回放和复杂图表编辑。

### 4.3 控制

提供六路 GPIO 开关、风扇 1/2/3/4 档以及 CS1237 通道切换。每次操作显示
STM32 返回的实际状态和结果码，不以按钮状态代替设备确认。

### 4.4 固件升级与日志

选择 `.bin` 文件后，可请求应用从 115200 baud 进入 bootloader，再以
460800 baud 执行擦除、写入、校验和重启。界面显示阶段、进度、结果和详细
日志。默认固件名为 `DM3.1_BAT_app.bin`，但允许选择其他测试固件。

固件升级与日志页显示时间、收发方向、帧 ID、原始十六进制数据和操作结果，
并支持保存为文本文件。

## 5. 串口发现与跨平台处理

使用 `serial.tools.list_ports` 枚举端口：

- Windows：`COMx`；
- Linux：通常为 `/dev/ttyACM*`；
- macOS 开发验证：通常为 `/dev/cu.usbmodem*`。

升级引起 USB 重枚举时，优先根据原端口的 USB serial number、VID 和 PID
寻找同一设备；无法唯一匹配时停止自动连接并要求用户重新选择，避免连接到
错误设备。

## 6. 数据记录

用户手动开始或停止 CSV 记录。每行使用本机单调采样顺序和带时区的墙钟
时间戳，字段包括：

- 风扇档位、fan1 RPM、fan2 RPM、按键位图；
- 三路超声波距离、有效位图和错误位图；
- CS1237 原始值、通道、有效标志和错误码；
- GPIO 位图和链路状态。

缺少新样本的字段保留最近值，并额外写入各数据源的采样时间，便于识别陈旧
数据。停止记录、断开连接和退出程序时刷新并关闭文件。

## 7. 错误处理与升级安全

- 串口拔出、超时或读写异常：标记离线、停止轮询和控制、保留日志；用户手动
  重连；
- CRC、长度或未知帧错误：记录原始上下文，不更新对应状态；
- STM32 控制错误响应：恢复界面到设备实际状态并显示结果码；
- 固件文件：升级前验证文件可读、非空且大小不超过现有 bootloader 允许的
  应用区；
- 升级失败：停止后续步骤并保留 bootloader 状态和日志，不自动重复写入；
- 升级期间禁用普通控制，防止共享串口被其他命令占用。

## 8. 测试与验收

复用现有协议、SerialHost 和 bootloader 单元测试，并新增最小必要检查：

1. 模拟串口下，轮询、控制和错误响应能更新正确的界面数据模型；
2. 升级期间普通轮询停止，成功或失败后状态转换正确；
3. CSV 表头、样本时间和关闭行为正确；
4. Qt 离屏模式下窗口可以创建和关闭。

不做像素级截图测试。首版验收需要在 Windows 和 Linux 各完成一次：

- USB CDC 连接、拔插和重连；
- 状态监控、控制、曲线与 CSV；
- 从运行态进入 bootloader，升级 `DM3.1_BAT_app.bin` 并恢复连接；
- 独立打包产物在无源码目录中启动。

## 9. 首版完成标准

- 一个 STM32 可稳定连接并完成全部现有应用协议操作；
- 界面在查询超时和固件升级期间保持响应；
- 曲线连续运行 30 分钟无无界内存增长；
- CSV 和日志可用于复盘通信及传感器问题；
- Windows 和 Linux 均有各自构建并验证过的可执行产物。
